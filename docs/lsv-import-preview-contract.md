# Read-only save evidence preview — frozen Round 2 contract v1

Status: implementation-ready Round 1 contract. Research-only documentation; no product behavior is enabled here. Ownership proof and instance continuity are not prerequisites for this preview. **No additional research is required to implement this conservative MVP.**

## Thirty binding product decisions

1. Intake: one explicitly selected local `.lsv` File, checked by signature and package structure, not trusted by extension/MIME. No directories, URL imports, batch scanning, archive filesystem extraction or automatic recent-file access.
2. Scope: LSPK v18 only, non-solid, one-part, using only existing supported codec profiles; exact `Globals.lsf`, validated LSF v7 metadata format 0, existing bounded codecs. Other supported archive members are not inspected. Missing Globals is unsupported, not empty inventory. This reuses the already-proven Globals identity path; it is not fresh Globals research, a LevelCache/Globals join, or an ownership collector.
3. Processing: browser Worker only, on-device; no server, upload, telemetry or fallback service. Main thread transfers the file buffer; payload decoding and raw identifiers stay in the Worker.
4. Privacy: never send filename, campaign/character names, raw Stats/CurrentTemplate, UUIDs, payload values, node indices, coordinates, hashes or save paths to logs, analytics, persistent storage, UI result state or backend. Existing extractor intermediates remain private Worker memory. Unexpected errors become fixed safe codes, never exception messages/stacks.
5. Ceilings: file/member 128 MiB each; entries 512; cumulative decoded bytes 512 MiB; string 1 MiB; depth 64; report 10 MiB. Generic structural nodes 400,000 / attributes 655,360 / index 32 MiB / names 8 MiB / 4,096 attributes per node / 12M traversal steps. Identity candidates 16,384 / catalogue rows 1,024 / IDs per row 64 / identifier UTF-8 256 bytes / result 8 MiB / aggregate extraction+matching 2M identity steps. These are ceilings, not promised supported workloads. Do not raise them. Research neighborhood limits are not product limits and do not authorize an oversized LevelCache product path.
6. One original 30s end-to-end attempt deadline covers intake, Worker startup, archive extraction, structural validation, extraction, catalogue matching and safe projection. Pass remaining time to each stage; never reset it. Retain existing independent parser/structural/identity work caps. Host watchdog terminates overdue Workers. Cancel terminates and clears state; no partial result after failure/cancel/timeouts.
7. Matching: exact case-sensitive validated Stats-family token only from `Items/ItemFactory/Items/Item` in validated Globals. Type 20/22 as existing extractor supports. No holder or container assumption. Exclude CacheTemplates definitions. Malformed supplied identity stays unsupported and does not fall back.
8. Duplicate save records: aggregate by canonical catalogue key, retaining evidence-record multiplicity. It is **not item quantity** and not unique instances. Never auto-deduplicate claimed instances or sum Amount values.
9. Ambiguity: one token resolving to several catalogue keys yields one ambiguous family group containing every candidate key; do not choose the first, intersect by name, or invent a tie-breaker.
10. Unmatched means valid supported family evidence with zero catalogue matches. Report aggregate counts in Full only, not raw records/tokens; never construct a new catalogue row.
11. Unsupported identities are separate from malformed/unsupported whole-file results. An unsupported field may produce an unsupported record under the existing reviewed extractor rules. A structural/codec failure rejects the whole attempt; no usable partial preview.
12. Absence has no negative implication. Unmatched, unsupported, omitted, withheld and absent are never translated to unowned/not-found. Do not enumerate catalogue absences as import results.
13. Ownership is always `unknown`; instance identity is always `unresolved`. These are orthogonal properties on evidence, not exclusive matching classes. No Owned/Equipped/In party badges or import/apply controls.
14. Provenance: fixed `EXACT_STATS_FAMILY` flag, validated Globals ItemFactory scope, canonical catalogue revision. Family evidence proves a matching record representation, not live presence or inventory ownership. B/A research findings do not classify a user's save.
15. The Story's existing Minimal/Light/Full mode controls display via the existing reviewed catalogue spoiler projection. Project first, then search/filter/group/count/recommendation-like summaries/DOM/a11y. Do not feed import evidence into tracker recommendations or classifiers.
16. Counts: Minimal/Light show only visible matched catalogue-family count; suppress evidence occurrence totals, ambiguous/unmatched/unsupported counts and source/raw totals. Full may show evidence-record counts and aggregate unmatched/unsupported counts, labelled evidence records, never quantity or ownership. Full ambiguous groups retain all candidate keys.
17. Minimal/Light: no save Level, exact acquisition, source/vendor/NPC, hidden IDs, coordinates or diagnostic evidence in counts/search/filter/badges/title/aria/hidden DOM. Existing catalogue policy permits item names/type/rarity; preserve that policy rather than inventing a new visibility roster. Light may use only existing reviewed catalogue broad-region projection, never save Level. For MVP hide ambiguous groups entirely in protected modes. Show an unconditional fixed limitation message in both modes, independent of hidden counts: “This mode shows catalogue matches only. Additional save diagnostics are available in Full details.”
18. CurrentTemplate is **excluded from catalogue matching**. The save-current-template namespace remains unscoped save-local data, not a static catalogue template. Do not convert/relabel it to `template`, join it to Creator, or use it to reduce Stats ambiguity. No raw CurrentTemplate leaves Worker.
19. Canonical catalogue is the tracker's already-validated ingested 555-item snapshot (556 raw source rows), retaining complete existing gameIds and stable key `(act+'|'+name).toLowerCase()`. No raw-source duplicate matching. Await canonical catalogue readiness; if identity coverage is unavailable/fallback-incomplete, return CATALOGUE_NOT_READY. No implicit network fetch in import.
20. Order: validate complete canonical catalogue/IDs; extract reviewed Globals candidates; ignore save-current-template as a matching namespace; exact Stats lookup; classify 0/1/many; aggregate by exact keys; project minimal fixed DTO in Worker; apply spoiler presentation on main thread. Exact canonical-key lexical sorting is deterministic; source order never means semantic priority.
21. No fuzzy/name/wiki/location matching, substring/case folding of Stats, subset-ID matching, new URL aliases, positional joins, generic UUID fallback, or heuristics. Existing catalogue ingestion/resolver/classifiers remain unchanged.
22. Many records -> one key: one matched row with `occurrences` (evidence records) in the private result DTO; display that only in Full. Never multiple progress checkboxes or duplicate tracker rows.
23. One record -> many keys: explicit ambiguous group, all keys sorted and preserved. Aggregate identical candidate-key sets with occurrence counts; attempt-local group IDs are opaque counters, never derived from private values. Full explanation: “This family evidence matches more than one catalogue entry.” No ownership inference.
24. File statuses: READY, MALFORMED, UNSUPPORTED, RESOURCE_LIMIT, TIMEOUT, CANCELLED, CATALOGUE_NOT_READY, FAILED. Error response has no matches, summary, diagnostic cardinalities or partial data. Match classes: MATCHED_CATALOGUE_EVIDENCE, AMBIGUOUS_CATALOGUE_MATCH; aggregate UNMATCHED_SAVE_RECORD / UNSUPPORTED_RECORD_IDENTITY. Ownership/instance remain unknown/unresolved for all classes.
25. Loading: finite stages READING, VALIDATING_ARCHIVE, EXTRACTING_GLOBALS, VALIDATING_RESOURCE, MATCHING, PROJECTING, READY. Coarse stage updates only, no invented percentage, payload-derived text or per-record private details. Request-generation IDs reject stale replies. Selecting another file, closing preview or changing Story cancels and clears the old attempt before new intake. Mode changes reproject existing safe DTO, cancel unsafe pending reveals, never restart decoding.
26. Fixed copy: “Save evidence is not proof of ownership. Missing evidence does not mean you do not own an item. This read-only preview does not change your Story or progress.” Label the feature “Save evidence preview”; never “Owned items import”. Label multiplicity “evidence records”. Explain unsupported limits without naming private fields/values.
27. No raw save evidence or preview results persist. Worker termination and clearing references are best-effort lifecycle cleanup, not a guarantee of forensic memory erasure. No download/export of raw diagnostic report.
28. No localStorage/sessionStorage/IndexedDB/cookies/Cache API writes for import. Read existing active Story mode/catalogue snapshot through current app interfaces only. No new persistence requirement.
29. File never leaves device. Do not introduce network requests; dependency/runtime assets load normally before import, not a remote parsing service. Test with remote requests blocked and record zero backend requests. No real account/browser profile for automated QA.
30. Forbidden writes: Story/progress/ownership/found flags, spoiler preferences, auth/session, sync/backend/Supabase/SQL, themes, PWA/service-worker registration, versioned transport, catalogue identities/classifiers. Preview is read-only and isolated from tracker forms/state. Do not add Apply/Import progress buttons.

## Versioned product DTO

The accompanying `docs/lsv-import-preview.schema.json` is the closed version-1 boundary. Only a successful READY result contains evidence. A catalogue revision identifies the public dataset snapshot, not the save. Keys are canonical public catalogue keys validated against the pinned snapshot; no private raw IDs are allowed. `coverage` is a fixed enum, not a claim of whole-save/inventory coverage. `attemptId` travels in the outer Worker protocol only; no private identifiers are encoded in it.

READY example (fabricated public catalogue key):

```json
{"version":1,"kind":"SAVE_EVIDENCE_PREVIEW","status":"READY","coverage":"GLOBALS_ITEMFACTORY_STATS_ONLY","catalogueRevision":"public-dataset-revision","matchedEvidence":[{"class":"MATCHED_CATALOGUE_EVIDENCE","catalogueKey":"act 1|synthetic example","evidence":"EXACT_STATS_FAMILY","occurrences":2,"ownership":"unknown","instance":"unresolved"}],"ambiguous":[],"unmatched":{"class":"UNMATCHED_SAVE_RECORD","count":0},"unsupported":{"class":"UNSUPPORTED_RECORD_IDENTITY","count":0},"limitations":["NOT_OWNERSHIP","NO_ABSENCE_INFERENCE","INSTANCE_UNRESOLVED","PARTIAL_SAVE_SCOPE"]}
```

Error example: `{"version":1,"kind":"SAVE_EVIDENCE_PREVIEW","status":"RESOURCE_LIMIT"}`. No private exception payload or partially successful rows. Validate incoming Worker messages against this closed boundary and catalogue snapshot; unknown fields/statuses/keys fail closed. DTO internal counts are not display counts: spoiler-safe visible view models are recomputed before DOM/search/counts.

## Round 2 — one autonomous implementation milestone (A–J)

A. **Intake:** local file picker inside separate read-only preview panel; check extension/signature/size, explicit action, no folder/history scan. Preserve tracker form/node/focus/scroll/pending state on entry/exit. Story change cancels and clears.
B. **Worker:** minimally package only proven parser/resource/codec/inventory dependencies needed for Globals. Prefer deterministic generated product adapter/bundle without importing research workbench/controller or exposing experiments. Keep existing generic APIs/limits unchanged. Transfer file bytes; bound catalogue snapshot/protocol; reuse exact Stats extractor/matcher with CurrentTemplate ignored. No LevelCache neighborhood collection in product.
C. **Lifecycle:** one 30s deadline, watchdog, generation tokens, finite loading stages, cancellation/termination, sanitized error codes, no partial/stale results. Test delayed replies, replacement and unmount while parsing.
D. **Matching projection:** pinned canonical catalogue, complete ID validation, Stats-only exact matching; deterministic grouping, all ambiguous keys retained; closed schema-v1 DTO; no raw values escape Worker. Reuse existing aggregate identity budget. Reject unavailable catalogue identity coverage.
E. **State:** in-memory attempt-local DTO and projected view model only. ownership unknown / instance unresolved. Clear on file/Story change/close; mode transitions invalidate reveals and recompute view, search, filters, groups and counts. No tracker progress mutation.
F. **UI:** “Save evidence preview”, prominent fixed limitations, visible read-only matches; Full-only evidence multiplicity/ambiguity/aggregate diagnostics; no apply/write action. Empty means no visible supported evidence, not unowned. Fixed safe errors and retry via a fresh explicit user-selected attempt only.
G. **Spoilers:** existing Story projection before every observable surface, no hidden-data count differences or source filtering leaks; hide ambiguous/diagnostic groups in Minimal/Light, fixed unconditional explanation. Full acquisition display stays behind existing disclosures/policy. Stricter transitions atomically remove content from DOM/a11y and reset local reveals.
H. **QA:** permanent table-driven identity, ambiguity, privacy, resource caps, output DTO, stage/deadline, cancellation, stale Worker and spoiler regressions. Tracker node/state/focus/scroll and Story isolation; keyboard/focus/a11y at 320/390/768/1280, disposable browser context with remote writes/storage blocked. Package exact intended runtime inventory; tests/research/docs/scripts remain excluded. Existing PWA/transport/DEV gate unchanged.
I. **Real-save QA:** only a separately user-authorized local file/attempt through the finished product path, payloads in memory, source fingerprint/stat before/after, no private output committed. No private reread is authorized by this Round 1 contract itself. Unsupported/limit/error is an honest product outcome; do not broaden codecs/resources or retry research automatically. Validate visible contract, not ownership.
J. **Develop preview:** after Work review and explicit shipping authorization, commit/push develop only and inspect exact Cloudflare preview assets/package, DEV PREVIEW, exclusions, read-only UI and representative responsive smoke. No main/production/tag/PR unless separately authorized. Current Round 1 authorizes no new commit/push/deploy for these changes.

### Complete Codex implementation instruction

Implement A–J above as one autonomous read-only Save evidence preview milestone on develop, using schema v1 and all thirty decisions as binding. Leave work uncommitted for Work review unless the new user task explicitly authorizes shipping. Do not return between internal stages; solve routine engineering/test/packaging/UX issues, run relevant focused and full QA, preserve protected systems, and produce a reviewable checkpoint. ### Round 2 hard stops

Stop only affected line and report before: raised limits; codec/layout expansion; new private scalar collector; Globals joins/Creator/ECS/holder inference; matching by CurrentTemplate/fuzzy name; ownership/progress apply behavior; backend/storage/upload; real-save access without explicit authorization; unsafe browser profile; production changes; PWA or transport activation. Continue unaffected safe implementation. Optional ownership/continuity/control-save/extra-domain work is POST-MVP research, never a preview prerequisite.
