## Implementation and provenance

`experiments/lsv/zstd-bounded.cjs` is a readable checked derivative/reference
implementation using fzstd 0.1.1 entropy-table and baseline algorithms, attributed
to Arjun Barrett with its MIT notice retained in full. Reference:
https://github.com/101arrowz/fzstd/tree/v0.1.1/src/index.ts
Format contract: https://www.rfc-editor.org/rfc/rfc8878.html
The original `vendor/fzstd-0.1.1.js` and adjacent notices are unchanged. The
unchecked vendor decoder is no longer a runtime dependency of the research
Worker; no external codec or native decoder is used in the browser/runtime path.

The parser calls the checked module's frame inspection and decode API. Decode
reuses the same inspection implementation, including direct module callers;
there is no parallel schema or alternate permissive decoder. The outer checks
reject forbidden frames before destination allocation. Type-2 stored sizes
measure compressed bytes, not regenerated bytes; only raw/RLE lengths contribute
to exact preflight expansion accounting. Regenerated compressed output is checked
during sequence execution and against the final expected length.

The decoder checks forward/reverse bit availability, entropy distributions and
states, literal boundaries, one/four Huffman stream consumption, jump-table
ranges, sequence counts/modes, prior-table availability, repeat offsets, actual
history availability, window distances and remaining capacity before writes.
Zero-sequence sections and sequence/Huffman streams must be fully consumed.
Regenerated literal counts are checked against remaining member capacity before
RLE/Huffman scratch allocation, not only before copying to the destination.
Huffman-weight FSE streams use their distinct state-update-overflow termination
rule; both initial states must have their full `2 * table.log` bits available
before that termination rule can apply. A truncated-initialization review vector
now rejects through direct decoding, parser decompression, selected-member reads
and the actual Worker entry. Post-initialization termination remains unchanged.
The original two malformed history/overproduction review vectors also fail during
checked decoding, even though the original vendor can produce apparently
correct-length results for both.

Output uses one pre-sized destination, also used as history. Literal scratch is
at most 128 KiB and entropy tables have format-specific bounds. No second
member-sized destination or frame-window copy is allocated. Existing input/
member 128 MiB, cumulative 512 MiB, entry 512, string 1 MiB, depth 64, report
10 MiB and cumulative active Worker 30-second caps are unchanged. Compressed and
regenerated blocks are each bounded by min(window, 128 KiB). The controller's
hard termination remains essential for synchronous entropy work; between-block
scheduling permits cancellation observation. Direct APIs are for bounded
synthetic tests, not unisolated real-save processing. Workers are not a hard
memory sandbox; no physical-mobile feasibility claim is made.

## Supported boundary

One standard dictionary-free, checksum-free frame with raw, RLE and checked
compressed blocks. Existing bounded content-size-present/absent handling is
retained. Permitted compressed behavior includes literal raw/RLE/Huffman/treeless
forms, one/four Huffman streams, predefined/RLE/FSE/repeated sequence tables,
repeat offsets, overlapping matches and cross-block history. Invalid structures
are rejected; this does not authenticate bytes or detect every arbitrary
mutation that forms another valid stream.

Still rejected: dictionary fields/external dictionaries, checksummed frames,
skippable/concatenated frames, trailing data, reserved flags/types and unknown
layouts. LSPK remains v18/single-part/non-solid; framed LZ4 resources remain
unsupported. No fallback or magic scanning is added.

### Supported subset and validation

- One standard frame, version 1, with one data block, or a valid empty frame.
- Stored or compressed block; independent or dependent flag. A single dependent
  block starts with empty history, so no cross-block history is introduced.
- Standard block maximum codes (64 KiB through 4 MiB); actual allocation depends
  on the validated section output size, never the advertised block maximum.
- Optional 64-bit content size must fit existing caps and equal the section size.
- Mandatory descriptor checksum, reserved bits, all input ranges, block length,
  EndMark, exact frame consumption and exact output length are validated.
- Only the validated compressed block payload enters the unchanged bounded raw
  LZ4 decoder. Stored lengths agree before allocation/copy; empty output is zero.

Dictionaries, block/content checksum variants, multiple data blocks, concatenated
frames, skippable/legacy frames, trailing bytes and unknown options remain
unsupported. Malformed headers/checksums/ranges and invalid raw matches reject.
The wrapper is not added to archive codec dispatch. Other LSF versions/layouts
retain their previous policy. Raw string-table handling, table/attribute/graph
validation and all existing limits remain unchanged.

Resource parsing validates all section ranges and preflights every framed
section before any section decompression. It reserves total section expansion
in the existing shared attempt budget before decoding/allocating section output.
The wrapper uses one bounded destination through the existing raw decoder;
there is no additional member-sized copy. Worker loading includes the new module;
request isolation, transfer behavior, cancellation and the cumulative 30-second
active execution deadline are unchanged. Invalid/unsupported resource structure
continues to be reported separately from successful outer-member extraction.
Real-save processing remains Worker-only. Research remains excluded from dist.

### Explicit research operation

`inspect-resource-frames` Worker request after package inspection. The exact

The existing parser performs outer extraction with the existing shared budget.

`resource-framing` response with no payload buffer and no transferables. No
workbench/product UI or deployment path is added.

Resource decoding and framing inspection share one LSF header/section-layout
parser. Inspection is restricted to v7 / format 0 / LZ4. It reports the physical
strings/nodes/attributes/values/keys layout, validates all section ranges and
prospective expansion against the existing attempt budget, and inspects framed
non-string sections. It neither expands nor parses raw strings or any table/value
section. Section expansion is not charged as consumed because it never occurs;
outer member extraction remains charged normally.

`lz4-frame-bounded.inspectFraming()` validates standard magic/version, descriptor
flags and BD, optional content size against the LSF declaration, the mandatory
header checksum, every block header/stored size/payload range, EndMark and exact
frame exhaustion. It permits multiple block envelopes for observation only.
Dictionaries, block/content checksum variants, reserved options, legacy/skippable
frames, concatenation and trailing bytes remain rejected. Both independent and
dependent flags can be observed without decoding history.

A fixed 4,096-data-block limit applies to each frame, including empty stored
blocks; a 4,097th block rejects. Reports contain only bounded structural metadata:
frame flags/sizes, checksum validation, declared expected output, block counts,
stored/compressed counts, each block's index/payload offset/stored size/type, and
EndMark/exhaustion status. Their status is `framing-validated`, with payload
validation and section decoding explicitly `not-attempted`. No names, values,
identifiers, decoded tables or payload bytes are returned. In particular, framing
success does not certify compressed payload syntax, regenerated lengths, valid
matches/history, LSF graph validity or gameplay semantics.

Existing input/member 128 MiB, cumulative expansion 512 MiB, cumulative active
Worker 30-second and entry/string/depth/report limits are retained. Framing loops
check cancellation/deadlines and yield every 64 blocks. Reports are bounded during
construction and again at resource/Worker boundaries. There are no decoded-section
output allocations or section-decoder calls. The original `inspect()`/`decode()`
policy remains single-block; archive/raw LZ4 and Zstandard code is unchanged.

## Bounded multi-block LZ4 decoder checkpoint — awaiting Work review

### Shared bounded raw-block primitive

`parser.decodeLz4BlockInto(input, destination, outputOffset, outputLimit,
historyStart, options)` validates safe integer ranges, fixed byte caps and
non-aliasing before writing, checks every literal/offset/extension read and
literal/match write bound, preserves progressive overlapping matches and terminal
sequence validation, and returns the actual output cursor. It allocates no output
and charges no budget. Buffer lengths are rechecked after yields so caller-side
detachment/resizing cannot silently clip subsequent writes. Shared destinations
are rejected because distinct shared-buffer wrappers may alias; the raw wrapper
still accepts shared input into its own nonshared destination. Existing raw LZ4
`decompress()` still allocates its exact output, starts with empty history and
requires the final cursor to equal the declared size.

For each dependent block, the frame decoder supplies
`historyStart = max(0, blockStart - 65535)`. Every match must have a nonzero 16-bit
distance within both available written history and the 65,535-byte maximum.
Previously copied stored bytes and regenerated compressed bytes become history;
no separate history buffer is allocated. Existing independent single-block
handling starts with empty history. No independent multi-block support is added.

### Frame/resource integration and budgets

`inspectForDecode()` reuses the same bounded framing walker as public
`inspectFraming()`, then applies decode policy. Public inspection keeps its report
limits, metadata-only status and zero-section-decode behavior. Private decode
plans are count-bounded and do not serialize public per-block reports. No
caller-supplied inspection result is trusted as validation; decoding rechecks its
own envelope. Resource parsing preflights all framed sections before allocation,
then reserves total section expansion once through the existing shared budget.

Multi-block output uses one exact section destination. Each compressed block
writes directly into it, with an output limit of
`cursor + min(blockMaximum, sectionLength - cursor)` and an actual returned
cursor. Stored blocks copy only after payload/output-capacity checks. Final output
must equal the LSF declaration; block lengths are never inferred from position.
Direct frame callers may supply a checked expansion budget; the primitive does
not charge per block, and the resource path does not double-charge sections.

Cancellation remains checked during tokens/long matches and between blocks.
The raw primitive yields after 64 KiB of progress; frame processing also yields
for stored/short-block runs, at most 16 short blocks between scheduling points,
without duplicating a full compressed block's yield. The existing cumulative
30-second controller deadline and all byte/report/string/depth limits remain
unchanged. No larger timeout or allocation cap is introduced.
